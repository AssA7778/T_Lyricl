# tglyrics

**لیریکِ زنده و سینک‌شده‌ی آهنگی که داری گوش می‌دی، توی بیوی تلگرامت.**

خط‌به‌خط، دقیقاً سرِ همان لحظه‌ای که خواننده می‌خواند.

```
♪                                    ← ساز
شب که می‌شه دلم می‌گیره               ← 00:12.34
                                     ← 00:16.80  ساز
یاد اون روزا که با هم بودیم           ← 00:18.20
```

---

## اول اینو بخون: چیزی که کار **نمی‌کند**

قبل از نوشتن این پروژه چهار مسیر بررسی شد. سه‌تاش بن‌بست بود و بهتره
بدونی چرا، تا وقتت رو سرشون تلف نکنی:

| مسیر | وضعیت | چرا |
|---|---|---|
| **Spotify Web API** | ❌ با اکانت فری | خودِ endpointِ خواندن پریمیوم نمی‌خواهد، **ولی** از ۱۱ فوریه ۲۰۲۶ اسپاتیفای شرط گذاشته که *صاحبِ اپ* در Development Mode باید پریمیوم داشته باشد. ضمناً از ۱۸ ژوئن ۲۰۲۶ refresh token بعد ۶ ماه منقضی می‌شود و سقف تست‌یوزر از ۲۵ به ۵ رسیده. |
| **SoundCloud** | ❌ کاملاً | هیچ endpointای برای «الان چه چیزی پخش می‌شود» ندارد — نه در API عمومی، نه در api-v2 داخلی. فقط تاریخچه‌ی پخش دارد که موقعیت ندارد. لیریک هم اصلاً ندارد. |
| **آهنگ پروفایل تلگرام** | ❌ کاملاً | `users.getSavedMusic` فقط لیستِ فایل‌هاست. پخش سمتِ بیننده اتفاق می‌افتد و هیچ رویدادی به سرور نمی‌رود — حتی برای خودت هم نامرئی است. |
| **Last.fm / اسکروبل** | ❌ برای این کار | «now playing» دارد ولی **بدون موقعیت**. فقط می‌گوید چه آهنگی، نه اینکه کجایش. برای سینکِ لیریک بی‌فایده است. |

**نتیجه: موقعیتِ دقیقِ پخش فقط از خودِ دستگاهی که دارد پخش می‌کند در می‌آید.**

و این در عمل از همه‌ی بالایی‌ها **دقیق‌تر** است: اسپاتیفای `progress_ms` را
با ۰.۵ تا ۱.۵ ثانیه تأخیرِ تصادفی می‌دهد (باگ شناخته‌شده و حل‌نشده)، ولی
`currentTime` مرورگر و `PlaybackState` اندروید مقدارِ واقعیِ خودِ پلیرند.

## معماری

```
  دستگاهِ پخش‌کننده                VPS تو                        تلگرام
 ─────────────────────         ────────────────────────         ────────
  یوزراسکریپت مرورگر            وب‌هوک
  (YouTube Music /        ──►   └─► ساعتِ درون‌یاب
   SoundCloud /                     (موقعیت را بین دو پیام
   Spotify Web /                     با ساعتِ مونوتونیک
   Apple Music)                      ادامه می‌دهد)
                                          │
  یا: MPRIS لینوکس                LRCLIB ─┤ کش SQLite
  یا: ایجنت ترماکس                        │ + فایل‌های .lrc دستی
                                          │
                                     رندرِ ۷۰ کاراکتری
                                     (خط بلند ← اسکرول سینک‌شده)
                                          │
                                     زمان‌بند ──────────────►   بیو
                                     (سرِ دقیقِ هر تایم‌استمپ،
                                      منهای تأخیرِ اندازه‌گیری‌شده)
```

سه تصمیم که بقیه‌ی چیزها از آن‌ها می‌آید:

**۱. موقعیت درون‌یابی می‌شود، نه پرسیده.** دستگاه فقط وقتی چیزی عوض شود خبر
می‌دهد (پلی/پاز/سیک/آهنگ جدید) بعلاوه‌ی یک ضربان هر ۱۰ ثانیه. بینِ پیام‌ها
موقعیت با `time.monotonic()` جلو می‌رود. یعنی رزولوشن نامحدود، ترافیک صفر،
و مصون از تنظیمِ ساعتِ سیستم.

**۲. تأخیر جبران می‌شود، دو بار.** یوزراسکریپت ساعتش را به سبک NTP با سرور
هماهنگ می‌کند و می‌گوید «این عدد را در فلان لحظه‌ی *ساعتِ تو* گرفتم» —
تأخیرِ شبکه از عدد در می‌آید. سمتِ تلگرام هم تأخیرِ `updateProfile` مدام
اندازه‌گیری می‌شود و درخواست همان‌قدر **زودتر** فرستاده می‌شود تا دقیقاً
سرِ تایم‌استمپ روی سرور بنشیند.

**۳. صف نداریم.** اگر محدودیتِ نرخ اجازه‌ی نوشتن ندهد، فریم را نگه نمی‌داریم
که بعداً بنویسیم. صبر می‌کنیم و **از نو حساب می‌کنیم** «الان چه خطی باید
باشد». پس در بدترین حالت بعضی خط‌ها رد می‌شوند، ولی هیچ خطی با تأخیر نوشته
نمی‌شود. عقب‌افتادن بدترین حالت است، چون از آن به بعد کلِ آهنگ ناهماهنگ
می‌ماند.

## نصب روی VPS — یک خط

روی سرور (اوبونتو/دبیان، با root):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AssA7778/T_Lyricl/main/install.sh)
```

اسکریپت پایتون و venv را می‌سازد، کاربر سرویس درست می‌کند، سرویس systemd را
ثبت می‌کند، یک توکنِ تصادفی برای وب‌هوک تولید می‌کند و همان‌جا پیشنهاد
می‌دهد سشن تلگرام را هم بسازد (api_id/api_hash از my.telegram.org + شماره و
کد تأیید). **دوباره اجرایش کنی = آپدیت** — `config.toml` و `data/` و
لیریک‌های دستی‌ات دست نمی‌خورند.

دستورهای بعدی را به آخر همان دستور اضافه کن:
`status` / `logs` / `restart` / `login` / `uninstall`

اگر موقع نصب سشن نساختی، بعداً:

```bash
sudo bash /opt/tglyrics/install.sh login
sudo journalctl -u tglyrics -f
```

## وصل‌کردن پلیر

### مرورگر (پیشنهادی — دقیق‌ترین و ساده‌ترین)

۱. [Tampermonkey](https://tampermonkey.net) یا Violentmonkey را نصب کن
۲. `userscript/tglyrics.user.js` را بازش کن تا نصب شود
۳. از منوی افزونه → **⚙️ تنظیم سرور tglyrics**
   - سرور: `http://آی‌پی‌سرورت:8787`
   - توکن: همان `token` داخل `config.toml`
۴. **🔌 تست اتصال** را بزن

کار می‌کند روی: YouTube Music، SoundCloud، Spotify Web، Apple Music،
Tidal، Deezer، یوتیوب معمولی.

> **روی گوشی؟** فایرفاکس اندروید + افزونه‌ی Violentmonkey + همین
> یوزراسکریپت. با موزیک را توی مرورگر گوش بده. ساده‌ترین راهی است که روی
> موبایل جواب می‌دهد.

اگر برنامه روی همان کامپیوتری اجرا می‌شود که آهنگ پخش می‌کند:

```toml

kind = "mpris"
```
```bash

```

Wireless debugging و adb دارد و خروجی‌اش بین برندها فرق می‌کند. اول راهِ
فایرفاکس بالا را امتحان کن.

### اسپاتیفای

اگر کسی با پریمیوم برایت اپ بسازد و تو را تست‌یوزر کند (اکانتِ تستی لازم

## ریسکِ FLOOD_WAIT — صادقانه

هیچ پروژه‌ی متن‌بازی در دنیا لیریکِ زنده در بیوی تلگرام ندارد. نزدیک‌ترین
چیزها bot‌های «آهنگ فعلی» هستند که هر ۱۵ تا ۶۰ ثانیه *چک* می‌کنند و چون تا
آهنگ عوض نشود متن تکراری است، عملاً **هر ۳-۴ دقیقه یک بار** می‌نویسند.

لیریکِ زنده یعنی هر ۳ تا ۸ ثانیه یک نوشتنِ **واقعی**، چون هر خط با خط قبلی
فرق دارد و هیچ‌کدام قابل حذف نیست. یعنی ده‌ها برابر بیشتر. تلگرام هم هیچ
عددِ رسمی‌ای منتشر نکرده و صریحاً می‌گوید محدودیت‌ها قابل پیش‌بینی نیستند.

پس عدد را **حدس نمی‌زنیم، یاد می‌گیریم**:

- با یک فاصله‌ی محافظه‌کارانه شروع می‌شود (`min_interval`)
- هر `FLOOD_WAIT` ⇒ همان‌قدر که تلگرام گفت می‌خوابد **و** فاصله نمایی بالا می‌رود
- بعد از یک دوره‌ی آرام، فاصله آرام‌آرام برمی‌گردد پایین (ولی هرگز زیر `hard_floor`)
- مقدار یادگرفته‌شده در `data/rate_state.json` می‌ماند، پس ری‌استارت از صفر شروع نمی‌کند
- یک سقفِ سختِ مستقل هم هست: `max_writes_per_minute`
- متنِ تکراری **هرگز** فرستاده نمی‌شود (شمارنده‌ی ۴۲۰ تلگرام روی «متد + پارامتر» کلید می‌خورد، پس نوشتنِ بی‌تغییر هم خرج دارد)

اگر محافظه‌کارتر می‌خواهی:

```toml
[rate]
min_interval = 6.0
max_writes_per_minute = 10
```

نتیجه: بعضی خط‌های کوتاه رد می‌شوند، ولی هرچه نشان داده می‌شود دقیقاً
سرِ وقتِ خودش است.

> در گزارش‌های موجود، محدودیتِ بیو به‌صورت flood wait ظاهر می‌شود نه بن.
> ولی هیچ‌کس در این نرخ داده‌ای منتشر نکرده — تو داده‌ی بهتری از هر منبعِ
> موجود خواهی داشت. با `.lrc` وضعیت را ببین.

## ۷۰ کاراکتر، و کاری که با آن می‌کنیم

اکانت معمولی ۷۰ کاراکتر بیو دارد، پریمیوم ۱۴۰. (سقف واقعی موقع اجرا از خودِ
تلگرام پرسیده می‌شود، هاردکد نیست.) خیلی از خط‌های لیریک بلندترند.

به‌جای بریدن، خط بلند **سینک‌شده اسکرول** می‌شود:

```
00:41.20   بگو کجای این شهر بی‌ستاره                    (۳۸ کاراکتر)
00:43.85   دنبال یه بهانه می‌گردی که برگردی               ← تیکه‌ی بعدیِ همان خط
```

اگر لیریک کلمه‌ای (A2) باشد، مرزِ تیکه‌ها دقیقاً روی تایم‌استمپِ همان کلمه
می‌نشیند. اگر نباشد، به‌تناسبِ طولِ متن. `min_chunk_ms` جلوی این را می‌گیرد
که خطِ کوتاه به ده تیکه‌ی سریع بشکند و نرخِ نوشتن منفجر شود.

می‌خواهی بریده شود؟ `long_line_mode = "truncate"`.

## لیریکِ فارسی

LRCLIB لیریکِ فارسیِ سینک‌شده دارد، ولی یک تله‌ی بزرگ:

| جستجو | نتیجه | سینک‌شده |
|---|---|---|
| `Mohsen Yeganeh` | ۸ | ۷ |
| `Sirvan Khosravi` | ۱۰ | ۹ |
| `Googoosh` | ۹ | ۸ |
| `محسن یگانه` | **۰** | — |

متادیتای LRCLIB فینگلیش است، با اینکه خودِ متنِ لیریک فارسی است. اگر اسم را
همان‌طور که از پلیر می‌آید بفرستی، فکر می‌کنی هیچ آهنگ فارسی‌ای لیریک ندارد.

برای همین `lyrics/translit.py` هست: اسم فارسی را خودکار فینگلیش می‌کند و چند
کاندیدا را امتحان می‌کند (اصل، فینگلیش، فقط عنوان، …). یک جدول از خواننده‌های
پرتکرار هم دارد که ترنسلیتِ خودکار خرابشان می‌کند.

**متنِ نمایشی هیچ‌وقت دست نمی‌خورد** — فینگلیش‌سازی فقط برای *پیدا کردن* است.
آهنگ فارسی با خط فارسی نشان داده می‌شود.

آهنگی که LRCLIB ندارد؟ فایلش را دستی بگذار — `lyrics/HOWTO.txt` را ببین.
هرچه آنجا باشد بر آنلاین اولویت دارد.

## کنترل از داخل تلگرام

توی **Saved Messages** بنویس:

| دستور | کار |
|---|---|
| `.lrc` | وضعیت: آهنگ، موقعیت، منبع لیریک، نرخ، تعداد فلاد، تأخیر |
| `.lrc on` / `.lrc off` | روشن/خاموش (خاموش ⇒ بیوی اصلی برمی‌گردد) |
| `.lrc sync +300` | لیریک را ۳۰۰ms جلو ببر — برای همان آهنگ ذخیره می‌شود |
| `.lrc sync -250` | عقب ببر |
| `.lrc sync 0` | صفر کن |
| `.lrc reload` | کش را پاک کن و دوباره دنبال لیریک بگرد |
| `.lrc bio متن` | بیوی حالتِ بیکار |
| `.lrc help` | راهنما |

پیام خودت با جوابش جایگزین می‌شود، پس Saved Messages شلوغ نمی‌شود.

`http://سرورت:8787/status` هم همه‌چیز را به JSON می‌دهد.

## عیب‌یابی

**بیو عوض نمی‌شود**
```bash
journalctl -u tglyrics -f
curl http://localhost:8787/status | python3 -m json.tool
```
اگر `playback.track` خالی است، یوزراسکریپت به سرور نمی‌رسد → **🔌 تست اتصال**
را بزن. اگر `stale: true` است، دستگاه بیش از ۴۵ ثانیه خبری نداده.

**پیدا شد ولی لیریک ندارد** → `.lrc reload`، یا `simulate.py` را با
`--duration` امتحان کن، یا فایل `.lrc` دستی بگذار.

**یک‌کم جلو/عقب است** → `.lrc sync +250`. سراسری: `global_offset_ms`.

**فلاد می‌گیرد** → `min_interval` را ببر بالا. برنامه خودش هم بالا می‌برد؛
`.lrc` مقدارِ یادگرفته‌شده را نشان می‌دهد.

**بعد از کرش، بیوی اصلی برنگشت** → دفعه‌ی بعد خودش برمی‌گرداند: بیوی واقعی
در دیتابیس نگه داشته می‌شود و برنامه تشخیص می‌دهد آخرین چیزی که *خودش*
نوشته چه بوده.

**پورت بسته است**
```bash
sudo ufw allow 8787/tcp
```

## امنیت

- `config.toml` شاملِ **StringSession** است = کلیدِ کاملِ اکانتت. `chmod 600`،
  و توی گیت کامیت نکن (`.gitignore` هست).
- `token` وب‌هوک را حتماً عوض کن. بدون آن هر کسی که آی‌پی سرورت را بداند
  می‌تواند بیوت را عوض کند.
- بهتر: پورت را روی اینترنت باز نکن و از Cloudflare Tunnel یا nginx با TLS
  استفاده کن. یوزراسکریپت با `https://` هم کار می‌کند.
- هرگز دو پروسه را روی یک سشن اجرا نکن — شایع‌ترین دلیلِ باطل‌شدنِ سشن است.

## تست‌ها

```bash
python -m unittest discover -s tests -t .
```

۱۳۹ تست، بدون شبکه، بدون اکانت. مهم‌ترین‌هایشان:

- `test_rate.py` — محافظِ فلاد با ساعتِ ساختگی: عقب‌نشینی، بازیابی، سقف، عدمِ گرسنگی

- `test_lrclib.py` — انتخابِ درستِ آهنگ، مخصوصاً حالتِ «متادیتای فارسی ← دیتابیسِ فینگلیش»
- `test_writer.py` — رفتار در برابر FLOOD_WAIT، ABOUT_TOO_LONG و قطعیِ شبکه
